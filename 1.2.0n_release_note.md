# SwitchU fork 1.2.0n

The daemon can start Nintendo's applets for Breeze (interface 5), and the
CI builds just the daemon on every push.

Only the daemon changed in this release; the 1.2.0m menu works with it. Breeze
beta126.00 needs this daemon for Album, Mii Maker, Change Button Mapping,
Internet connection and Add user on its Games screen. With an older daemon
those entries say so and do nothing.

## Applets started for Breeze

Started from Breeze itself, Album and Mii Maker crashed (miiEdit) or hung, and
a hang left the system out of service sessions until a reboot. These applets
work only when the HOME program starts them, the way it does for the SwitchU
menu.

Breeze now writes the applet's name to `config/SwitchU/breeze_open_applet`
(`album`, `mii`, `remap`, `netconnect` or `usercreator`) and closes. The daemon
sees that Breeze has gone, closes hbmenu at once instead of waiting for HOME,
starts the applet, and opens Breeze again when the applet closes, not the
SwitchU menu. A game stays suspended behind it. `fork.txt` now reads
`interface=5`.

The user page and the friend screens are not offered: Breeze runs in the User
Page slot, so starting the user page would start Breeze. System Settings cannot
be offered either. Its applet is not on retail consoles: the HOME program draws
the settings itself.

Checked on the console (firmware 23.0.1, Atmosphere 1.12.1): the applets open
from Breeze and Breeze comes back after each one.

## CI

A push now builds only the daemon, in release mode, and uploads
`home_daemon.zip`. The first run took 22 minutes, 19 of them building
libstratosphere from scratch; libnx, libstratosphere and xmake's packages are
now cached. A tag, or Run workflow, builds the whole install and makes the
draft release, as before. The debug and homebrew builds are gone: no release
used them.

The daemon folder's `fork.txt` and Breeze loader are now installed by the
daemon target itself, so a daemon-only build gives a complete
`home_daemon.zip`.
